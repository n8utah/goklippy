# PCA9685 Servo Board

Up to 16 extra servos per board, driven over the MCU's I2C bus. The approach follows the
[Basically sorter](https://github.com/basicallysource/sorter-v2) (`software/firmware/sorter_interface_firmware/PCA9685.cpp`):
the chip runs at 50 Hz and keeps each servo's pulse going by itself, so the MCU only
relays a short register write when an angle changes.

goklippy uses stock Klipper firmware for this. The MCU gets a plain I2C device
(`config_i2c` + `i2c_set_bus`), and the host writes the chip's registers with
`i2c_transfer`. The firmware must be built with I2C (`CONFIG_WANT_I2C`, on by default for
the atmega2560 build).

## Wiring (RAMPS 1.4 / Arduino Mega)

| PCA9685 | Arduino Mega |
|---------|--------------|
| SDA | D20 (PD1) |
| SCL | D21 (PD0) |
| VCC | 5 V (logic only) |
| GND | GND |
| V+ | separate servo supply (e.g. 5–6.5 V); its ground joined to GND |

Don't power servos from the RAMPS 5 V: an MG995 can pull 2 A when it starts.

## Config

Add it from **Board Setup → All servos → PCA9685 servo boards → + Add board**, or write
the sections yourself:

```ini
[pca9685 servo_board]
i2c_bus: twi            # the Mega's only hardware bus (default)
i2c_address: 0x40       # board default; set by the A0–A5 solder jumpers
#i2c_speed: 100000
# Software I2C on any two pins instead of i2c_bus:
#i2c_software_scl_pin: ar21
#i2c_software_sda_pin: ar20

[servo door0]
pin: servo_board:pwm0   # board name : channel pwm0–pwm15
minimum_pulse_width: 0.0005   # 0°   (Klipper default 0.001)
maximum_pulse_width: 0.0025   # 180° (Klipper default 0.002)
maximum_servo_angle: 180
```

Board servos appear in the servo panel with the GPIO ones, and work in groups the same way.

## Behaviour

- **On connect** the board is put to sleep, set to 50 Hz (prescale 121), woken with
  auto-increment, and every channel is turned fully off, so no servo moves until it is
  told an angle.
- **Checking the board is there.** The AVR I2C driver ignores missing acknowledges, so a
  write to an empty address still "succeeds". Setup therefore reads the prescale register
  back; an empty bus reads 0xff. If it doesn't match, connect still succeeds, the server
  logs `pca9685 not ready`, and each servo move tries the setup again, so the board can be
  powered after connecting.
- **Board status in the UI.** Right after connecting, and whenever you press **Check
  boards**, the app reads each board's MODE1 and PRE_SCALE registers
  (`POST /api/v1/mcu/sessions/:id/pca9685/check`) and shows a badge per board:
  - **Working**: the chip answered and is set to 50 Hz. If it answered but had reset
    (power lost on VCC), it is set up again and the message says so.
  - **Not found**: both registers read 0xff, so nothing is at that address. Check the
    wiring, VCC, and the address jumpers.
  - **Error**: the I2C transfer failed, usually because the MCU shut down on a stuck bus.
  - **Not checked**: the board is in the config but not in this session (added after
    connecting).
  A failed servo move now shows its error in the servo panel too.
- **A stuck bus shuts the MCU down.** If SDA or SCL is held low (shorted, or an unpowered
  board dragging the lines down), the AVR gives up after 5 ms with `i2c timeout` or
  `Failed to send i2c start`, and Klipper shuts the MCU down. Fix the wiring and connect
  again; connecting clears the shutdown.
- **Angles** map linearly from `minimum_pulse_width` at 0° to `maximum_pulse_width` at
  `maximum_servo_angle`, rounded to the chip's 4096 steps per 20 ms (about 4.9 µs each).

Code: `backend/mcu/cfgtranslate/pca9685.go` (config) and `backend/mcu/session_pca9685.go`
(registers).
